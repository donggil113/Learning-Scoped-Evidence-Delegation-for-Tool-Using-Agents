\begin{abstract}
Tool-using agents must copy values from untrusted content into tool arguments.
Prior work enforces provenance at the level of tool calls, parameters, and
spans (CaMeL, PACT, ROPE, ARGUS). It leaves open which admissible span should
bind to each argument when several candidates pass the policy. We ask whether
a small \emph{trained} binder, which can only propose a candidate or abstain
and never widens permissions, improves secure task success over rule-based
field scopes and over a prompted-LLM binder at matched cost.

\section{Setting}
\subsection{Threat model}
Trusted planner fixes control flow; attacker controls untrusted content (and,
in one variant, a delegated sender account).
\subsection{Fixed boundary}
Typed tool schemas; capability validator (type, per-argument provenance scope,
requested-scope equality, confidentiality flow, limits, budget).
Every executed call is re-checked against the reference field-level boundary.
\subsection{Binder interface}
Input: trusted task, requested scope, candidate span and provenance.
Output: candidate id or \textsc{Abstain}.
